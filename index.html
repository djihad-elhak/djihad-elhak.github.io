1.1

SpermNet: sperm motility analysis on two CPU cores

A clinician reads motility as a ratio, so every false detection counts as an immotile cell. Over seven months I took a heavy YOLO11m and DeepSORT baseline and rebuilt it around that number: a detector 53 times smaller, a tracker that needs no appearance model, a calibration that was measured instead of assumed, and a desktop application a laboratory can run without a GPU.

Context
Research internship, CERIST, Data Science Unit
Period
Sept. 2025 to Mar. 2026
Output
Desktop application, single-author preprint in preparation
Stack
PyTorch, OpenCV, ONNX Runtime, NumPy, FastAPI, Electron, React, TypeScript

Heads are about 10 pixels wide and up to 218 of them share a frame, so I designed SpermNet for that scale: a 375,621-parameter U-shaped network with a stride-2 centre-point output and a three-channel input (the frame, its difference from the clip's temporal median, and the temporal gradient). Tracking is gated by motion alone. A stage-micrometer test then showed that estimating the scale from head length was off by 38.7%, so velocities now come from the optical train, and a scale-free criterion reproduces the three-class report within 1.5 points without any scale.

The engine is exported to ONNX with verified numerical parity and runs behind FastAPI inside an Electron application: worklist, overlay review against the original video, calibration management, reports in PDF, CSV and Excel in English and French, roles and a hash-chained audit log.

1.2

On-premise GenAI platform for flight software

A platform an embedded software team can run on its own GPUs, built and measured on NASA's F´ flight framework. An agent writes the missing requirement-tagged unit tests, and a test only counts once the real build, the test run and mutation testing prove it, and an engineer accepts it.

Context
Personal research project
Period
2026
Output
Code, live demo, 6-page paper
Stack
Python, LangGraph, MCP, llama.cpp, vLLM, hybrid retrieval, Docker, GitHub Actions

The code and its 560 requirements are loaded into a knowledge graph served over the Model Context Protocol. A LangGraph agent works through the traceability gaps one at a time on its own branch, a GPU sizing model calibrated on measured runs says how many GPUs a team needs, and a web console puts it in front of engineers.
